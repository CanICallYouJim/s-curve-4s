# Сборка и публикация обновлений S-кривой

Публичный репозиторий программы: `CanICallYouJim/s-curve-4s`. В нём находятся только исходники приложения, иконка и ресурсы сборки; музыка и личные файлы не публикуются.

`release.yml` следует разместить в `.github/workflows/release.yml` публичного репозитория. Сохраняйте структуру `tools/windows-fade`, `tools/macos-fade`, `tools/scurve-release`.

При push в `main`, pull request и ручном запуске Actions выполняются сборки и проверки. Windows запускается на `windows-latest`, универсальная Mac-сборка — на `macos-15-intel`. На обычном push обновление пользователям не публикуется. Тег `vX.Y.Z` запускает те же проверки и публикует GitHub Release только после успеха обеих платформ.

## Выпуск следующей версии

1. Измените код и увеличьте `appVersion` в `tools/windows-fade/update.go`, например с `1.2.0` на `1.2.1`.
2. Проверьте изменения, сохраните коммит и отправьте его в `main` публичного репозитория.
3. Создайте и отправьте тег с этой же версией: `git tag v1.2.1`, затем `git push origin v1.2.1`.
4. Дождитесь успешного workflow **Build and release S-curve**. В Release появятся `S-curve-4s-Windows.exe`, `S-curve-4s-macOS.zip` и `update.json`.

Обе сборки получают версию тега через `build.py --version`, поэтому версия приложения, manifest и Release совпадают. Пользовательский лаунчер проверяет `https://github.com/CanICallYouJim/s-curve-4s/releases/latest/download/update.json`. Если новая версия ещё не опубликована или сеть недоступна, установленная программа остаётся доступной.

Windows-ресурс — самостоятельный EXE. Mac-архив содержит только корневое приложение `S-кривая 4 с.app`, без исходников и посторонних файлов: это формат установщика обновлений. Приложение Mac имеет локальную ad-hoc подпись; публикация Release не заменяет нотариальное заверение Apple.

## Проверки и зависимости

FFmpeg 9.1 скачивается с закреплённых URL и проверяется по SHA256, записанным в workflow. Для Mac проверяются обе архитектуры, нативный self-test и полная подпись bundle. Windows выполняет проверки параметров запуска, ожидания окна, реального диалога, истории, спрайта и обновлений. Тест настоящего окна должен быть реализован как `TestWindowsDialogSmoke`; исключать его для получения зелёной сборки нельзя.

Секреты в файлы не записываются. Для публикации workflow использует краткоживущий встроенный `GITHUB_TOKEN` с правом `contents: write`, только в job публикации. Токен пользователя программе не нужен.

## Локальное создание manifest

`python3 tools/scurve-release/make_manifest.py 1.2.0 --windows dist/S-curve-4s-Windows.exe --macos dist/S-curve-4s-macOS.zip --output dist/update.json`

Скрипт проверяет формат версии, имена ресурсов и вычисляет SHA256 по фактическим файлам. При повторной сборке пересоздайте manifest: нельзя оставлять хеш от прежнего EXE или ZIP.
